# 无限画布集成路线图

## 目标与状态

在尽量保留 infinite-canvas 既有图片画布交互与工程结构的前提下，明确接入 new-api 登录认证、模型 Relay、云端工程、精选词库和数字资产所必需的差异，形成可实施的集成方案。

规划已收敛，可进入实施：产品范围、复用原则、认证与模型接入方向及工程云端存取行为均已确认。具体模型名单、接口与存储结构、更新检查方式和协议适配验收在实现阶段完成。本文不表示集成已经实现或通过验收。

## 已确认方向

### 复用上游交互

- 默认保留上游已有的画布操作、资产选择、资产插入与节点收录体验，只调整本站接入所必需的部分。
- 资产库接入重点是替换本地数据源、映射数据结构和接入用户权限，不重新设计拖拽或双向交互协议。
- 工程持久化沿用上游工程文档结构，按保留的能力保存必要内容，不重新定义一套画布内部模型。
- 功能范围约束用户可见能力；具体代码裁剪必须依据依赖关系，不以文件名或删除清单代替分析。

### 首期产品范围

- 在 new-api 的“AI 应用”中提供画布入口，保留主站导航；画布提供中文界面。
- 聚焦图片画布，不开放视频、音乐及独立 Agent 工作流；不提供图片超分能力。
- 用户无需配置 API Key、Base URL 或外部同步服务，模型请求通过本站 Relay 调用并沿用本站计费。
- 提供经验证的受控图片模型集合；提示词修饰、图片反推等辅助能力使用固定 LLM，具体名单在实现阶段维护。
- 精选词库使用本站数据，个人资产使用本站数字资产，不依赖外部词库作为本站精选内容来源。

### 认证与模型接入

- 主站已登录的用户打开内嵌画布即可使用，无需再次登录或配置。主站管理登录、会话刷新和退出，画布通过小型宿主接口取得有效认证头，直接请求本站 Relay，并保留请求取消及流式结果处理。
- 复用主站已有会话能力，不在画布另建认证体系。会话失效交由主站统一处理；认证凭据仅供运行时请求使用，不写入画布配置、工程或本地持久化。
- 面板 Access Token 通过 `Authorization` 携带，不作为上游通用 API Key 配置；不同模型协议统一接入本站会话认证。具体宿主接口形式在实现阶段确定，按同域受信任子应用设计，不将同域内嵌视为安全隔离。
- 独立维护画布模型与能力配置，定义允许的操作、参数范围和请求协议；不自动继承作图广场全部模型。作图广场已有实践作为候选与复用依据，具体名单和辅助 LLM 选择不阻塞初期规划。
- 能力配置同时驱动界面和发送前校验，结合用户实际可用模型决定可执行范围。打开已有工程也校验其模型和参数，不因旧数据绕过限制；模型不可用时明确提示，不擅自换模型执行。
- 受控名单是画布的产品范围，不是新增的服务端授权规则。本站 Relay 继续执行用户原有权限、分组及计费规则，不改变用户在其他 AI 应用或 API 中的权限。
- 保留上游操作入口、交互流程及可复用的请求构造与解析，在必要位置适配本站认证与协议。实现阶段逐项验证后开放能力，不复制整套作图广场，也不预先建设全站通用 AI 调用框架。

### 工程云端存取

- 长期定位为在线应用，不支持离线使用。云端是工程的唯一正式保存位置，按用户隔离；保留上游创建、打开、导入、重命名、删除和编辑体验。
- 修改后空闲时自动保存，只有服务端确认后才表示保存完成。短暂断网时保留当前页面内容并提示未保存，恢复连接后尝试保存；不承诺关闭页面后恢复未保存修改，离开前给予提醒。
- 用户回到已打开的画布时检查云端更新；没有未保存修改或进行中的工作需要保护时，自动跟进最新工程，不让普通的跨设备使用变成冲突处理。具体检查与协调方式保持简单，在实现阶段确定。
- 本地未保存修改与云端更新冲突时，保留本地内容并停止自动覆盖，允许另存为新工程，或放弃本地修改并打开云端版本；首期不提供强制覆盖或自动合并。
- 云端已删除的工程不因旧页面保存而复活；有本地未保存内容时可另存为新工程，否则提示删除并返回列表。
- 正常的连续编辑、自动保存和图片生成结果不应相互覆盖，也不应制造需要用户处理的冲突。

### 图片上云

- 生成结果、本地导入、粘贴、裁剪和分割产生的图片统一上云。
- 云端图片独立于数字资产。上传不自动收录；“存入资产”仅创建对已有云端图片的资产条目。
- 记录图片身份和存储信息，画布与图片资产通过图片 ID 使用图片；从已有图片资产加入画布时复用对象。
- 首期删除节点、画布工程或图片资产均不删除对应云端文件，不额外维护引用表、引用计数或回收任务。
- 接受云端图片持续占用存储、可能存在遗留对象的代价；未来有实际需要时再设计回收和存量关系重建。
- 上传、保存失败如实提示，不将失败标记为已同步；首期不建设完整的未同步草稿恢复体系。
- 使用公开读 S3，精选词库与云端图片复用通用存储能力。图片身份和写入操作仍须按用户授权；公开读不等于私密文件存储。

### 工程组织与交付

- 画布源码纳入根目录 `canvas/`，与 `web/` 独立依赖、独立构建，同仓提交、统一发布，不使用 Git Submodule。
- 控制台入口为 `/playground/canvas`，以同域子应用形式接入，复用主站认证能力。
- 子应用制品装配到 `web/dist/canvas/`，复用现有 Go 静态托管和发布流程；正确区分页面路由兜底与缺失静态文件的 404。
- 扩展现有 `makefile`、Docker 和开发编排，覆盖资源路径、开发代理及热更新，不另建一套交付流程。
- 体积与缓存按现有构建能力及实际验收结果处理，没有测量依据时不设独立优化规划。

## 不纳入本期

- 重新设计上游已有的画布、资产选择和插入交互。
- 多人实时协同编辑。
- 图片引用维护、自动回收、回收宽限期与续期机制。
- 完整的未同步草稿恢复体系。
- 私有签名 URL 及其刷新机制。
- 缺少实际问题或验收目标的专项性能优化。
