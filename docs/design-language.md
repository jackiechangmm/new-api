# 前端设计语言规范

## 1. 文档状态

- 状态：已确认，可作为设计系统实施依据
- 适用范围：`web/` 前端的全局视觉令牌、基础组件和设计系统展示页
- 视觉基调：瑞士现代主义平面设计 + 工程制图式网格
- 主题：暖白主题、深灰主题
- 品牌强调色：熔岩橙 `#E85F1A`
- 规范语言：中文

本文档是设计语言的单一规范来源。Prototype 只用于验证视觉方向，不覆盖本文档中的令牌值。

## 2. 核心原则

1. 使用平面化的几何构成、严格对齐和明确边界。
2. 默认形状为纯直角；只有确有必要时使用正圆或正半圆。
3. 默认无阴影；阴影只允许用于脱离文档流的浮层。
4. 网格是背景层，不进入卡片、面板、输入框、表格或其他组件内部。
5. 熔岩橙只作为品牌强调色和交互重点，不承担所有状态语义。
6. 所有用户可见状态必须同时具备视觉和语义表达，不得只依赖颜色。
7. 标题和正文使用同一套中性无衬线字体，只通过字号、字重和行高建立层级。
8. 等宽字体只用于技术信息、数据和尺寸标注，不用于普通中文正文。

### 3.3 颜色使用限制

- 不使用纯黑 `#000000` 或纯白 `#FFFFFF` 作为页面、文字或表面颜色。
- 不使用色彩渐变作为全局背景、组件背景或品牌主视觉。
- CSS `linear-gradient` 仅允许作为网格线的绘制算法，不得用于生成渐变色。
- `color.accent` 不用于成功、警告、错误和信息状态。
- 错误、警告、成功和信息状态必须同时包含文字、图标或可访问名称。
- 状态颜色不能仅通过低透明度细线表达。

## 4. 线条系统

### 4.1 语义类型

系统只定义三种线条语义：

| 令牌 | 线宽 | 用途 |
| --- | ---: | --- |
| `line.grid` | `1px` | 背景网格，最低视觉权重 |
| `line.structure` | `1px` | 组件边框、分隔线、结构边界 |
| `line.emphasis` | `4px` | 品牌几何构成、重要标记、展示性强调 |

交互状态使用独立线宽令牌：

| 令牌 | 线宽 | 用途 |
| --- | ---: | --- |
| `line.focus` | `2px` | 键盘聚焦和明确的交互焦点 |
| `line.error` | `2px` | 错误输入和错误组件边界 |

`line.axis` 不存在。系统不得新增坐标轴语义线。

### 4.2 线条颜色

- `line.grid` 使用当前主题的 `color.line.grid`。
- 次网格使用当前主题的 `color.line.grid-minor`。
- `line.structure` 使用当前主题的 `color.line.structure`。
- `line.emphasis` 使用 `color.accent`。
- `line.focus` 使用 `color.accent`。
- `line.error` 使用当前主题的 `color.error`。
- 所有线条默认使用实线，不使用虚线、点线和渐变线。

### 4.3 平衡型线条层级

默认线条方案为“平衡型”：

1. 网格退后，透明度低于结构线。
2. 结构线保持清晰，但不使用 `line.emphasis` 的粗度。
3. 熔岩橙线只承担指引、聚焦和重点构成。
4. 普通组件不得使用 `4px` 边框。
5. `line.emphasis` 不用于普通按钮、输入框、表格和卡片边框。

## 5. 网格系统

### 5.1 网格尺寸

| 令牌 | 值 | 启用范围 |
| --- | ---: | --- |
| `grid.primary-size` | `40px` | 页面和区域背景的默认网格 |
| `grid.minor-size` | `10px` | 展板和设计系统展示区域 |
| `grid.line-width` | `1px` | 所有网格线 |

- 非展板且非设计系统展示区域的所有页面只显示 `40px` 主网格。
- 展板和设计系统展示区域同时显示 `40px` 主网格和 `10px` 次网格。
- 次网格不得用于卡片、表格和表单组件内部。

### 5.2 网格渲染

基础网格使用可复用的 CSS 图层或 CSS gradient 生成，不使用固定图片作为基础网格。

网格图层必须满足：

- 令牌控制尺寸、颜色、透明度和主题适配。
- 网格可以挂载到页面背景或局部区域背景。
- 卡片、面板、输入框、表格和其他组件使用不透明的 `color.surface` 或 `color.surface-muted` 覆盖网格。
- 卡片内部不得显示网格。
- 页面背景网格默认从页面左上角统一对齐。
- 局部展板可以从自身左上角独立对齐。
- 局部网格不得使用未定义的任意偏移值。

复杂几何展板可以使用 HTML 或 SVG 绘制。静态图片只允许用于无法参数化的品牌图形，不得替代基础网格。

## 6. 形状与圆角

### 6.1 形状令牌

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `radius.none` | `0px` | 默认值，适用于所有组件和容器 |
| `radius.circle` | `50%` | 正圆 |
| `radius.semicircle` | `50%` 单侧边界 | 正半圆几何构成 |

### 6.2 使用规则

- 页面容器、卡片、面板、按钮、输入框、选择器、标签、表格和弹窗全部使用 `radius.none`。
- 正圆只用于状态点、头像、图表节点、明确的圆形对象和圆形图标容器。
- 正半圆只用于几何构成和方向性图形。
- 不提供 `radius-sm`、`radius-md`、`radius-lg` 等普通圆角令牌。
- 不得使用胶囊按钮、胶囊标签、圆角卡片或圆角输入框。

## 7. 阴影与表面

- 页面、卡片、面板、按钮、输入框、表格和普通组件不使用阴影。
- 下拉菜单、弹窗、抽屉等脱离文档流的浮层使用唯一阴影令牌：

```css
box-shadow: 0 8px 24px rgba(0, 0, 0, 0.16);
```

- 深灰主题的浮层同样使用上述阴影值，不增加第二套阴影规则。
- 表面层次通过 `color.background`、`color.surface`、`color.surface-muted`、边框和间距建立。
- 不使用发光、内阴影、长投影或渐变阴影。

## 8. 字体系统

### 8.1 字体族

系统只使用两类字体：

```css
--font-sans: 'Public Sans', 'Helvetica Neue', Arial, sans-serif;
--font-mono: ui-monospace, 'SFMono-Regular', Menlo, Monaco, Consolas,
  'Liberation Mono', 'Courier New', monospace;
```

- 标题、正文、导航、表单和普通 UI 文案使用 `font-sans`。
- ID、编号、时间、金额、比例、API 路径、模型名、代码、技术参数、尺寸标注和令牌值使用 `font-mono`。
- 不使用 Lora 或其他衬线字体。
- 不新增第三类字体。

### 8.2 字重

| 字重 | 用途 |
| ---: | --- |
| `400` | 正文、辅助文字 |
| `500` | 标签、表头、次要标题 |
| `600` | 操作标题、区块标题 |
| `700` | 页面标题、重要数值 |

### 8.3 字号和行高

| 令牌 | 字号 | 行高 | 用途 |
| --- | ---: | ---: | --- |
| `type.meta` | `12px` | `1.3` | 辅助信息、表格元数据 |
| `type.body` | `14px` | `1.5` | 默认正文、表单内容 |
| `type.body-emphasis` | `16px` | `1.5` | 强调正文、导航项 |
| `type.section` | `20px` | `1.1` | 区块标题 |
| `type.page` | `28px` | `1.1` | 业务页面标题 |
| `type.display` | `48px` | `1.1` | 设计系统展示标题 |
| `type.exhibition` | `64px` | `0.98` | 展板主标题 |
| `type.mono` | `12px` | `1.3` | 默认技术数据 |

- 业务页面不得使用 `type.display` 或 `type.exhibition` 作为常规标题。
- 不通过负字距或负字母间距制造紧缩效果。`letter-spacing` 默认使用 `0`。
- 标题与正文的差异只通过字号、字重和行高体现，不切换字体族。

## 9. 间距与组件尺寸

### 9.1 间距令牌

基础单位为 `4px`，页面主节奏使用 `8px`。

| 令牌 | 值 |
| --- | ---: |
| `space.1` | `4px` |
| `space.2` | `8px` |
| `space.3` | `12px` |
| `space.4` | `16px` |
| `space.6` | `24px` |
| `space.8` | `32px` |

不得在基础组件中使用未登记的间距值。

### 9.2 控件高度

所有高度包含内容、上下内边距和边框，使用 `border-box` 计算。

| 令牌 | 高度 | 用途 |
| --- | ---: | --- |
| `control.compact` | `28px` | 表格内操作、紧凑筛选 |
| `control.default` | `36px` | 默认按钮、输入框、选择器 |
| `control.large` | `44px` | 主要操作、触控优先控件 |

规则：

- 同一密度下，按钮、输入框、选择器和组合控件使用相同高度。
- 控件内文字、图标和边框以垂直中心线对齐。
- `compact` 使用 `12px` 文字，`default` 和 `large` 使用 `14px` 文字。
- 图标尺寸：`compact = 14px`，`default = 16px`，`large = 18px`。
- 图标与文字间距固定为 `8px`。
- 控件边框固定为 `1px`；聚焦和错误状态额外使用 `2px` 外框，不改变控件布局尺寸。

## 10. 交互状态

### 10.1 状态规则

| 状态 | 视觉规则 |
| --- | --- |
| 默认 | 显示 `line.structure`，不添加装饰性阴影或位移 |
| 悬停 | 使用 `color.accent-soft` 背景，或将局部结构线变为 `color.accent` |
| 聚焦 | 使用 `2px` `color.accent` 外框，保留键盘可见性 |
| 选中 | 使用 `2px` `color.accent` 结构线和 `color.accent-soft` 背景 |
| 禁用 | 文字、边框和图标使用 `color.muted` 的 `35%` 不透明度，禁止操作 |
| 错误 | 使用 `2px` `color.error` 外框，配合错误文字或图标 |

### 10.2 状态限制

- 错误状态不得使用低透明度的 `1px` 细线作为唯一提示。
- 错误状态的视觉强度必须与聚焦状态同等级别。
- 错误状态不得只依赖颜色；必须提供文字、图标或可访问名称。
- 不使用缩放、弹跳、强阴影或持续闪烁表达交互状态。
- `:focus-visible` 必须保留可见焦点外框。
- 视觉状态必须与 `aria-selected`、`aria-disabled`、`aria-invalid` 等语义属性保持一致。

## 11. 动效

动效不是全局固定风格，按页面性质选择以下模式：

| 模式 | 时长 | 缓动 | 使用场景 |
| --- | ---: | --- | --- |
| `motion.none` | `0ms` | 无 | 配置页面、数据密集页面 |
| `motion.short` | `160ms` | `ease-out` | 普通用户界面交互 |
| `motion.geometric` | `240ms` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | 首页、展板和视觉优先区域 |

- 动效只用于状态、展开、切换和加载反馈。
- 不使用弹跳、持续漂浮和无限循环的装饰性动效。
- 用户设置 `prefers-reduced-motion: reduce` 时，所有时长改为 `0ms`。

## 12. 图标和图形

- 普通操作图标使用项目现有的 Hugeicons 线性图标。
- 图标默认使用 `1px` 结构线视觉，不使用填充式大色块图标作为普通操作图标。
- 图标与文字遵循控件高度对应的 `14 / 16 / 18px` 尺寸。
- 自绘几何图形只用于展板、品牌构成和设计展示区域。
- 自绘图形必须使用本规范中的颜色、线宽、网格和形状令牌。

## 13. 组件实现约束

1. 组件不得自行定义新的颜色、圆角、线宽、字号、控件高度或基础间距。
2. 组件表面必须使用不透明主题表面，防止页面网格透入组件内部。
3. 组件边框、状态外框和内容尺寸必须使用 `border-box`，避免状态切换造成布局跳动。
4. 同一密度的控件必须共享高度、文字字号、图标尺寸和垂直对齐规则。
5. 卡片不得嵌套卡片；页面区域使用布局和分隔线表达，不使用装饰性浮动卡片。
6. 组件必须提供默认、悬停、聚焦、选中、禁用、错误和加载状态；组件不支持的状态必须在组件 API 中明确禁止。
7. 状态颜色必须同时满足视觉对比和语义可读性。
8. 新增页面必须明确选择是否启用页面背景网格；默认启用主网格，组件内部始终关闭网格。

## 14. 不在本轮固化的内容

以下内容不属于本设计语言令牌层，不能从本文档推导具体页面方案：

- 用户端、管理端、首页、配置页和聊天页的最终信息架构
- 各业务页面的布局、导航和内容密度
- 各组件的完整 API、数据模型和交互流程
- 具体页面使用 `motion.none`、`motion.short` 或 `motion.geometric` 的最终映射
- 具体业务组件的迁移顺序

这些内容必须在对应页面设计阶段单独决定，并遵守本文档已经确认的基础令牌和几何规则。
